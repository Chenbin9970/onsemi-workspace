# Ezairo 7160SL RSL10 解锁方法

## 背景

Ezairo 7160SL Hybrid 模组出厂烧有 Ezairo Pre Suite 固件，RSL10 的 NVR3 中写入了 JTAG 锁密钥，调试器无法连接。解锁本质是**擦除整个 Flash（含 NVR3）**，移除 JTAG 锁。

## 工具准备

| 工具 | 路径/来源 |
|------|----------|
| RSL10 Standalone FlashLoader | `D:\tool\RSL10_StandAlone_Flash_Loader\FlashLoader.exe` |
| 官方解锁工具 | `D:\tool\E7160SL_RSL10_Unlock_Tool_1.0(1)\unlock_RSL10_E7160SL.exe` |
| J-Link 调试器 | J-Link V9 或更新（ARM-OB STM32 不行） |
| J-Link 序列号 | 通过 `JLink.exe -NoGui 1 -CommandFile /dev/null -ExitOnError 1 -Device RSL10 -If SWD -Speed 4000 -AutoConnect 1` 查询 |

## 解锁步骤

### 1. 确认 J-Link 序列号

```bash
JLink.exe -NoGui 1 -CommandFile /dev/null -ExitOnError 1 -Device RSL10 -If SWD -Speed 4000 -AutoConnect 1 2>&1 | grep "S/N"
```

### 2. 执行擦除

**推荐方式：官方解锁工具**（内部自动抓 deep-sleep 窗口，最稳，实测一次成功）

```bash
# ① 先把 standalone FlashLoader 目录加进 PATH，否则工具内部 system("flashloader.exe") 找不到可执行文件
export PATH="D:\tool\RSL10_StandAlone_Flash_Loader:$PATH"
# ② 运行官方解锁工具
cd D:\tool\E7160SL_RSL10_Unlock_Tool_1.0(1)
unlock_RSL10_E7160SL.exe <JLink_SN> "D:\tool\RSL10_StandAlone_Flash_Loader"
```

成功输出 `Done!`。

**备选：直接 FlashLoader 手动擦除**（需抢上电窗口，受 deep-sleep 竞速影响，成功率低）

```bash
cd D:\tool\RSL10_StandAlone_Flash_Loader
FlashLoader.exe -u <JLink_SN> -s 4000 -v erase
```

参数说明：
- `-u <serial>` — J-Link 序列号
- `-s 4000` — SWD 速率 4000 kHz
- `-v` — 详细输出
- `erase` — 擦除全部 Flash（含 NVR3）

### 3. 验证

擦除成功后应正确识别为 Cortex-M3：

```
CPUID reg: 0x412FC231. Implementer code: 0x41 (ARM)
Found Cortex-M3 r2p1, Little endian.
```

### 4. 恢复蓝牙 MAC 地址

解锁会擦掉 NVR3 里的 `DEVICE_INFO_BLUETOOTH_ADDR`（`0x00081000`）。它一空，固件就回退到 BLE IP 的硬件默认地址 **`AB:89:67:45:23:01`**，于是**所有解锁过的板子 MAC 全都一样**。而产线写入的那个唯一 MAC 在 **NVR4** 里留了备份——NVR4 是出厂编程、用户不可写，**解锁不会擦它**，所以能还原。

> 顺序上只能放在解锁**之后**：解锁前板子被 JTAG 锁死，读不到 NVR4。

**① 读本机的 MAC 备份（NVR4）**

```bash
JLink.exe -NoGui 1 -Device RSL10 -If SWD -Speed 4000 -AutoConnect 1
```

```
J-Link> mem8 0x00081A20, 8
00081A20 = D4 A8 B1 46 00 F4 00 00
```

前 6 字节即本机 MAC（小端）。此例还原出来是 `F4:00:46:B1:A8:D4`。

**② 生成只含这 6 字节的 Intel HEX**

以 `D4 A8 B1 46 00 F4` 为例：

```
:020000040008F2
:06100000D4A8B14600F483
:00000001FF
```

> `0x00081000` 超过 16 位偏移，**必须带类型 04 的扩展线性地址记录**（第一行），否则会被当成 `0x00001000`，把数据写到 PROM 上去。

**③ 写进 NVR3**

```bash
JLink.exe -NoGui 1 -Device RSL10 -If SWD -Speed 4000 -AutoConnect 1
```

```
J-Link> loadfile D:\tmp\nvr3_mac.hex
J-Link: Flash download: Bank 3 @ 0x00081000: 1 range affected (2048 bytes)
J-Link> mem8 0x00081000, 8
00081000 = D4 A8 B1 46 00 F4 FF FF
```

J-Link V9.60 自带 RSL10 的 NVR bank（日志里的 `Bank 3`），不需要额外装设备定义。`loadfile` 自带复位。

**④ 验证**

- 芯片还是空的时候：回读 `0x00081000` 对上即可（没有固件，基带寄存器还没被配置，看不出结果）。
- 烧好固件后再确认射频实际用的地址（**不用扫码**）：

```
J-Link> mem32 0x40001524, 0x02
40001524 = 46B1A8D4 0000F400        ; 低4字节 + 高2字节，小端 → F4:00:46:B1:A8:D4
```

**注意事项**

- 写 NVR3 会**整扇区擦除 2 KB**（`0x81000-0x817FF`）。刚解锁的板子是空的，无损；但若 NVR3 里已有 `MANU_INFO_INIT`（`+0x80`）、JTAG 锁密钥（`+0x40`）等内容，会一并擦掉，动手前先 dump 一份。
- 每台板的备份值都不一样，**必须逐台读、逐台写**，不能共用同一份 HEX。
- 若某台 NVR4 也是全 `FF`（异常情况），说明备份也没了，只能另行分配地址。
- 根因分析与完整实测记录见 [开发/MAC地址与NVR3.md](开发/MAC地址与NVR3.md)。

## 常见问题

### 识别成 Cortex-M0 / CPU could not be halted

出厂固件上电后极快进入 deep sleep，调试器无法访问 CPU（CPUID 读为 `0x00000000`）。**拔掉 USB 重新上电**后立即执行擦除命令只能"抢窗口"，实测即使重上电后立刻跑手动 FlashLoader 仍失败（竞速赢不了）。**直接改用官方解锁工具**，它内部能处理 deep-sleep 窗口，无需拔插即可成功。

### FlashLoader 找不到

`FlashLoader.exe` 必须和 `JLinkARM.dll` 在同一目录下运行。

### 原厂 unlock 工具调用失败

`unlock_RSL10_E7160SL.exe` 内部通过 `system()` 调用 `flashloader.exe`，当它不在 PATH 时会报 "不是内部或外部命令" 并返回 `Failed to erase RSL10`。**解决：把 standalone FlashLoader 目录加进 PATH 再运行**，官方工具内部能抓 deep-sleep 窗口，比手动 FlashLoader 稳定得多：

```bash
export PATH="D:\tool\RSL10_StandAlone_Flash_Loader:$PATH"
cd D:\tool\E7160SL_RSL10_Unlock_Tool_1.0(1)
unlock_RSL10_E7160SL.exe <JLink_SN> "D:\tool\RSL10_StandAlone_Flash_Loader"
```

注意：该工具使用其目录下自带的 `JLinkARM.dll`（V6.16），不依赖系统安装的 SEGGER J-Link 版本（本机 V9.60 仍可用，工具不受影响）。

### FlashLoader `-f`（复位拉低）无法解决 deep sleep

`FlashLoader.exe -f` 会在连接时拉低复位线，但 7160SL 的复位线会**同时复位调试逻辑**（报 `Debug logic also reset by reset pin`），复位释放后 CPU 又立刻进 deep sleep，CPUID 仍读为 `0x00000000`，同样 `CPU could not be halted`。`-f` 不能替代"抢上电窗口"或官方解锁工具。

## 解锁后

NVR3 被擦除，以下校准数据丢失：

| 数据 | 影响 | 恢复方式 |
|------|------|---------|
| 蓝牙 MAC 地址 | 回退到硬件默认地址 `AB:89:67:45:23:01`，**所有解锁过的板子都一样** | 见上文「4. 恢复蓝牙 MAC 地址」 |
| 电压校准值 | 功耗测量偏差 | 运行 RSL10 SDK 中 `default_MANU_INFO_INIT` 例程 |
| JTAG 锁密钥 | 调试器可正常连接 | 不再需要 |

正常开发烧录前先手动跑一次 `default_MANU_INFO_INIT`（来自 RSL10 SDK），否则 BLE 可能因缺少校准数据表现异常。

> 该例程同样会「NVR3 地址为空 → 从 NVR4 读回」来恢复 MAC，但它是 µVision 工程，需要装 Keil；只恢复 MAC 的话直接用上面的「4.」更省事。
