# 工程复制改名注意事项

> 从现有工程（如 `peripheral_server_sleep`）复制出新工程并改名（如 `peripheral_server_sleep7160test`）时踩过的坑和修复方法。基于 2026-08-27 在 7160test 上的实际操作整理。

---

## 复制方式

```bash
cp -r peripheral_server_sleep peripheral_server_sleep7160test
```

文件系统复制会**保留全部旧工程名**，且 Debug 构建产物、RTE 生成文件原样带过来。改名后需要处理以下 3 个问题。

---

## 一、工程名（.project / .cproject）

### 现象
`.project` 里的 `<name>` 还是旧名，`.cproject` 的 refreshScope 自引用也是旧名，Eclipse 里工程显示旧名。

### 修改
`.project`：
```xml
<name>peripheral_server_sleep7160test</name>
```
`.cproject`（refreshScope 的 workspacePath 自引用，4 处）：
```xml
<resource resourceType="PROJECT" workspacePath="/peripheral_server_sleep7160test"/>
```

---

## 二、include 路径丢失（编译报 rwble_hl_config.h 找不到）

### 现象
Eclipse 重新生成 makefile 后，编译报：
```
rwip_config.h: fatal error: rwble_hl_config.h: No such file or directory
```
`rwble_hl_config.h` 位于 pack 的 `include/ble/`，但 makefile 里只剩 `.cproject` 显式写的 `include` 和 `include/ble/profiles`。

### 根因
编译需要的 3 个 RTE API include 路径（`include/bb`、`include/ble`、`include/kernel`）原本由 RTE 在生成 makefile 时补上；新复制工程重新生成时 **RTE 没有补**，于是只剩 .cproject 里显式写的路径。

对比（Debug/code/subdir.mk 的 pack include 路径）：
| | include | include/bb | include/ble | include/kernel | include/ble/profiles |
|--|:-:|:-:|:-:|:-:|:-:|
| 原 sleep（能编） | ✓ | ✓ | ✓ | ✓ | ✓ |
| 新 7160test（报错） | ✓ | ✗ | ✗ | ✗ | ✓ |

### 修复
把 3 个路径写进 `.cproject` 的 includePath（**fota / nofota / 活跃三份都要加**，否则切换 FOTA 会丢）：
```xml
<listOptionValue builtIn="false" value="&quot;${cmsis_pack_root}/ONSemiconductor/RSL10/3.9.1182/include/bb&quot;"/>
<listOptionValue builtIn="false" value="&quot;${cmsis_pack_root}/ONSemiconductor/RSL10/3.9.1182/include/ble&quot;"/>
<listOptionValue builtIn="false" value="&quot;${cmsis_pack_root}/ONSemiconductor/RSL10/3.9.1182/include/kernel&quot;"/>
```
Eclipse 重新生成 makefile 后路径即带上。若直接跑 `make`，需同步补进 Debug 下所有 `subdir.mk` 的编译命令。

### 验证
```bash
cd peripheral_server_sleep7160test/Debug && make main-build
```
能链接出 `peripheral_server_sleep7160test.elf` 即修复成功。

---

## 三、rteconfig 文件名必须跟随工程名

### 现象
Eclipse 报：
```
Error updating RTE project
Resource '/peripheral_server_sleep7160test/peripheral_server_sleep7160test.rteconfig' does not exist.
```

### 根因
CMSIS-Pack RTE 插件按**工程名**找 rteconfig 文件。工程改名后，插件找 `<工程名>.rteconfig`，但文件还叫旧名。

### 修复
1. 重命名 3 个 rteconfig 文件（用 `git mv` 保留历史）：
   - `peripheral_server_sleep.rteconfig` → `peripheral_server_sleep7160test.rteconfig`
   - `peripheral_server_sleep_fota.rteconfig` → `peripheral_server_sleep7160test_fota.rteconfig`
   - `peripheral_server_sleep_nofota.rteconfig` → `peripheral_server_sleep7160test_nofota.rteconfig`
2. 同步 3 份 `.cproject` 里的引用：
   ```xml
   <rteConfig name="peripheral_server_sleep7160test.rteconfig"/>
   ```
3. Eclipse 里刷新 / Close 后重开工程。

> 注意：FOTA 切换时 `cp` 的 rteconfig 文件名也要用新名（见下文）。

---

## 四、FOTA 切换在新工程上的差异

FOTA 开关流程（见 `docs/开发/FOTA功能.md`）不变，但**文件名要换成新工程的**：

```bash
cd peripheral_server_sleep7160test/RTE/Device/RSL10
cp startup_rsl10_fota.S startup_rsl10.S       # 或 nofota
cp sections_fota.ld sections.ld                # 或 nofota
cd ../..
cp peripheral_server_sleep7160test_fota.rteconfig peripheral_server_sleep7160test.rteconfig   # 或 nofota
# .cproject 同理 cp .cproject_fota / .cproject_nofota
# app.h 里 #define CFG_FOTA 取消注释 / 注释
```

---

## 五、Debug 目录残留

文件系统复制会把旧工程的 Debug 产物一起带过来（如 `peripheral_server_sleep.bin/.elf/.fota/.hex/.map`）。这些是 gitignored 的旧构建结果，建议删掉或 Clean 后重新构建，避免混淆。
