# 7160test — 音频杂音调试记录

> 工程：`peripheral_server_sleep7160test`
> 日期：2026-08-31
> 现象：手机经 RM（遥控麦克风）传音频到 PCM 输出（→7100）时有两个杂音
> 状态：**嗡嗡已修复（12k HPF）；金属尾音未解决（16k→12k 链路）；1k 纯音 2k 谐波确认不在 RSL10 数字链路（7100/后端嫌疑）**

## 一、结论速查

| 杂音 | 现象 | 来源 | 状态 |
|------|------|------|------|
| **嗡嗡** | 手机音量最小（近静音）时低频底噪 | DSP 解码输出里的 **~47Hz**（带 94/141Hz 谐波的失真低频） | ✅ **12k HPF 已修** |
| **金属尾音** | 音量中段以上、音乐（高频丰富）时"发亮/金属" | **16k→12k 链路**（ASRC DEC_MODE2 插值 或 7100，未定性） | ❌ 待办 |
| **1k 纯音 2k 谐波** | 仪器测 1k 纯音，1k 和 2k 位置都有峰 | **不在 RSL10 数字链路**（cap_in/cap_out 均标准 1k，2k<-49dB） | 7100/后端嫌疑，待查（见第六节） |

## 二、音频数据流（PCM 模式）

```
手机 RM → BLE → G722 解码(16k, Dsp2CmBuff0dec) → DMA ch3 → ASRC(DEC_MODE2 16k→12k)
   → DMA ch4 → pcm_tx_buf(12k, 双缓冲) → ch5 → PCM 从机 → SERO(DIO14) → 7100
```

## 三、抓数基建（cap_in / cap_out）

### 3.1 变量（app_func.c）

- `cap_in[1024]`：16k DSP 解码输出（DspDec_isr 抓，进 ASRC 前）
- `cap_out[1024]`：12k PCM 输出（出 ASRC 后，7100 实际收到的音频）
- `cap_in_idx` / `cap_out_idx` / `cap_done`（两路满 1024 → cap_done=1 冻结）
- `CAP_N=1024`（64ms@16k / 85ms@12k，FFT 分辨率 ~15.6Hz）

### 3.2 J-Link 抓数流程（JLink Commander）

地址每次构建变，从 `Debug/peripheral_server_sleep7160test.map` grep：
```
w1 <cap_done> 0        ; 复位
w4 <cap_in_idx> 0
w4 <cap_out_idx> 0
sleep 300
mem8 <cap_done> 1      ; 等 01（抓满冻结）
savebin cap_in.bin <cap_in> 2048    ; 1024×int16
savebin cap_out.bin <cap_out> 2048
```

**注意**：
- `cap_done=0 且 cap_in_idx=0` → DSP 没在解码（RM 链接断了/手机没在流），先恢复音频再抓
- J-Link 每次连接/读取目标前 grep 最新 map 地址（构建后地址会变）
- **`cap_out_idx` 地址紧跟 cap_out 数组尾**（如 `0x20001428`），不是 cap_out 数组头 `0x20000c28`。写错 → cap_out_idx 不复位（残留旧值 1024），cap_out 抓不到新数据、cap_done 假置 1（踩过坑，2026-09-01）
- J-Link `savebin` 相对路径存到 JLink.exe 当前目录，建议用绝对路径（`C:/tmp/cap_in.bin`），分析时注意别和旧文件混盘

### 3.3 分析脚本

`scripts/analyze_cap.py`（纯 Python FFT，无依赖）：
```
python scripts/analyze_cap.py cap_in.bin cap_out.bin
```
输出时域统计 + FFT 峰值 + 频带能量对比。

## 四、嗡嗡（47Hz）诊断与修复

### 4.1 数据特征

- 静音时 cap_in（DSP 解码输出）有 **~47Hz 强分量**（20~35dB 主导），带 **94Hz(-7dB)/141Hz(-13dB) 谐波**
- 波形尖锐不对称（-780 谷/+945 峰），是失真低频"嗡嗡"，非纯净正弦
- 0-500Hz 带比 500-2k 高 15-22dB
- 47Hz 穿过 ASRC 大小不变 → **不是 ASRC 极限环，是上游（DSP 解码输出）就有的**

### 4.2 修复：12k HPF（关键）

**位置**：`Pcm_asrc_out_dma_isr`（ch4 完成中断）里滤波 `pcm_tx_buf`（12k）。
- 宏 `TEST_HPF_12K`：级联 4 阶一阶 IIR，低切 ~100Hz@12k，`alpha_q15=31932`
- 实测：47Hz -13.5dB、300Hz+ 无损、DC 归零
- **`(acc+16384)>>15` 四舍五入**防向负截断引入 DC 偏置（不加会出 -19.7 DC）

### 4.3 关键教训：Dsp2CmBuff0dec 是 DSP/CM 共享内存，原位滤波无效

- 在 `DspDec_isr` 里对 `Dsp2CmBuff0dec`（DSP_DRAM4_BASE+160*4）做 in-place 滤波**完全无效**
  - DSP 每子帧重写解码数据，覆盖滤波结果（-25 DC 滤不掉、47Hz 压不掉就是证据）
- **必须改到 CM 独占的缓冲（pcm_tx_buf）滤波才生效**
- 16k 的 `TEST_HPF`/`TEST_LPF`（DspDec_isr 里）已废弃禁用

## 五、金属尾音诊断

### 5.1 数据定位

| 措施 | 嗡嗡 | 金属尾音 |
|------|------|---------|
| 12k HPF（fc=100） | ✅ | ❌ 无变化 |
| 12k LPF（4k/3k 后置，压 3-6k 达 9-15dB） | — | ❌ 听不出变化 |
| 16k AAF（fc=5k 前置防混叠，6-8k 压 9-10dB） | — | ❌ 无变化 |
| **OD 输出（16k→16k 无重采样、无 7100）** | — | ✅ **无金属尾音** |

### 5.2 关键结论

1. **cap_out（RSL10 发给 7100 的信号）频谱干净**——各频带 out-in≈0，无新增高频，LPF 压 3-6k 听不出变化 → **金属尾音不是 cap_out 的幅度/频谱成分**
2. **音乐有、纯语音没有** → 和音频高频含量（2-6k）直接相关
3. **OD 直通（DEC_MODE1 无重采样、无 7100）没金属尾音** → 但 OD 同时变了两个变量（ASRC 模式 + 去掉 7100），无法单独归因
4. 参照工程 `remote_mic_rx_rawtest1` 同样未解决，归咎"ASRC 16k→12k 3:4 非整数下采样固有伪影"，且"固定相位加重 → 需动态锁定 7100 12k 时钟"

### 5.3 定性

金属尾音来自 **16k→12k 链路**（ASRC DEC_MODE2 插值/相位伪影 或 7100 处理），RSL10 侧滤波（HPF/LPF/AAF/dither）全部无效。

## 六、1k 纯音 2k 谐波排查（2026-09-01 新增）

### 6.1 现象

- RM 传 1k 纯音，测试仪器在 **1k 和 2k 位置都有峰**
- 此前文档验证"写死 16k 1k 波形 → ASRC → PCM"输出正常 → 先确认真实解码链路（RM→G722 解码）输出的 1k 是否标准

### 6.2 抓数结论（cap_in/cap_out 双抓，两路满 1024、cap_done=1）

| 位置 | 1k 峰 | 2k-4k 频带 | 2k 相对 1k（Goertzel） | 47Hz |
|------|-------|-----------|----------------------|------|
| cap_in（16k 解码输出） | **+67.3dB** | 31.1dB | **-69.6dB**（1.5 LSB） | 31.3dB |
| cap_out（12k PCM 输出） | **+66.1dB** | 31.4dB | **-51.8dB**（11.7 LSB） | 30.9dB |

- 前 15 峰都不含 2000Hz；2k-4k 频带能量比 1k 低 ~38dB（近底噪）
- **连续 10 组抓数**（每 ~0.5s 一组）：cap_in 1k=4637~4650 LSB、THD 0.15%~0.32%；cap_out 1k=4489~4502 LSB、THD 0.19%~0.57%；幅度稳定、无瞬态失真
- cap_in/cap_out 各频带能量差 ≤1dB → ASRC 16k→12k 对 1k 转得干干净净
- 时域波形对称标准正弦（cap_in 峰值 ±4700 LSB，cap_out ±4800 LSB）

### 6.3 结论

**解码 → ASRC → PCM 全程数字信号是标准 1kHz，2k 谐波（<-49dB）不存在。测试仪器上的 2k 峰是 7100 或其后端（DAC/受话器/测量环节）引入的。**

待确认：
- 仪器测的是 7100 声学输出（受话器）还是电信号
- 2k 相对 1k 低多少 dB：若低 20-30dB → 受话器高 SPL 非线性嫌疑大；若接近 1k → 7100 DSP 压缩/增益削波嫌疑大

### 6.4 ASRC 输入粒度确认

**ASRC 每次送 8 个采样（SUBFRAME_LENGTH，1 个解码子帧），不是整帧 160。**

- `Audio_Init`/`Audio_Resume`：`Sys_DMA_ChannelConfig(ASRC_IN_IDX, RX_DMA_ASRC_IN, SUBFRAME_LENGTH, 0, Dsp2CmBuff0dec, &ASRC->IN)`
- 数据流：`DspDec_isr` 每次解码 8 个 16k 采样 → ch3 送 8 个到 ASRC->IN → ASRC 3:4 重采样出 6 个 → ch4 攒到 PCM_FRAME_WORDS=120（20 子帧=10ms）换 PCM 缓冲
- 每帧 160 = 20 子帧 → 产出 120 个 12k 采样（10ms @12k）
- ch3 是 `SRC_WORD_SIZE_32 → DEST_WORD_SIZE_16`，按打包规则把 DSP 写的 32-bit 字（每字 2 个 int16 采样）解包成 8 个采样喂 ASRC

### 6.5 抓数坑（本次新增）

- `cap_out_idx` 地址 = `0x20001428`（紧跟 cap_out 数组尾），不是 `0x20000c28`（cap_out[0]）。写错 → cap_out_idx 不复位、抓到旧数据、cap_done 假 1
- J-Link `savebin` 相对路径存到 JLink.exe 当前目录，建议绝对路径（`C:/tmp/...`）

## 七、软件重采样尝试（已回退）

### 7.1 方案

用软件多相 FIR 重采样器替换硬件 ASRC，消除 ASRC 插值伪影。
- 数据流：`DspDec_isr(16k) → 多相 FIR 3:4 → pcm_tx_buf(12k) → ch5`
- 阶段1：固定 3:4 比例（3 相位后来扩到 32 相位，解决变 inc 下的 frac 量化）
- 阶段2：audiosink 时钟跟踪（`inc=Cr/Ck`，相位累加器）

### 7.2 验证结果

- **数学正确**：1k/4k 正确通过（-0.5dB）、6k+ 防混叠、32 相位表；时钟跟踪 inc 正确匹配 7100 偏快 0.7%
- **实测断续**：音频断断续续，DSP 解码被拖停（frame_idx 卡住）→ 重采样在 DspDec_isr 里太重/时序问题
- **已回退**到硬件 ASRC（`RESAMP_SW` 宏关，代码保留可再试）

### 7.3 代码位置（如需再试）

`app_func.c` 的 `#ifdef RESAMP_SW` 块：`resamp_coef[32][32]` 系数表 + `Resamp_Process()`。
注意：
- 重采样只读 `Dsp2CmBuff0dec`（拷贝到 CM 的 `resamp_ring`），不碰共享内存
- 后续优化方向：重采样移出 DspDec_isr（单独 ISR/状态机），或减少每 DspDec_isr 的产出量
