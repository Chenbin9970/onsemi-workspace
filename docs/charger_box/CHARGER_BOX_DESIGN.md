## 机身功能定义

### 运行模式

| 模式 | 功耗 | 说明 |
|------|:---:|------|
| BLE 低功耗从机 | 600μA | BLE peripheral，低功耗待机 |
| RM RX | 900μA | 接收 RM 音频流 |

- 两种模式通过 **BLE 指令**互相切换
- 机身作为 BLE 从机（peripheral），充电盒作为 BLE 主机（central）

---

## 充电盒硬件架构

| 芯片 | 功能 |
|------|------|
| RSL10 | 运行 TX 工程，BLE 主机 + RM TX 向机身推流音频 |
| 经典蓝牙芯片（AD6976） | 连接手机，接收音频数据 |

```
手机 ──经典蓝牙──→ AD6976 ──DMIC──→ RSL10 ──RM TX──→ 机身
```

---

## 工作流程

### 无音频（待机）

- RSL10 处于 **BLE 主机模式**，同时连接两个机身
- 两个机身处于 **BLE 低功耗从机模式**（600μA）
- RSL10 维持 BLE 连接，监听音频

### 有音频（推流）

1. AD6976 收到手机音频 → 通过 DMIC 输入 RSL10
2. RSL10 通过 BLE 发送指令 → 机身切换到 **RM RX 模式**（900μA）
3. RSL10 自身切换到 **RM TX 模式**，开始推流
4. 两个机身同时接收音频

### 音频结束

1. RSL10 停止 RM TX，切回 BLE 模式
2. RSL10 通过 BLE 发送指令 → 机身切回 **BLE 低功耗从机模式**

## 充电盒方案设计

### 1. 音频检测方案

**问题**：AD6976 音频何时来、何时停，RSL10 如何感知？

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A. DMIC 能量检测 | RSL10 持续监听 DMIC，用 EMA 能量阈值判断 | 无需额外 GPIO | AD6976 噪声可能导致误触发 |
| B. AD6976 GPIO 信号 | AD6976 输出 audio_active 电平给 RSL10 | 准确可靠 | 占用一个 DIO，需确认 AD6976 是否有此引脚 |
| C. DMIC + 软件去抖 | 方案 A + 更长的 consecutive count | 改动小 | 切换延迟增加 |

**建议**：优先确认 AD6976 是否有音频状态输出脚。有则用方案 B，无则用方案 A。

### 2. BLE 模式切换协议

机身需要两个 BLE 指令：切 RM RX、切 BLE 从机。

**已有基础**：当前 TX 工程通过 Custom Service 写 `RM_ONOFF` (1/0) 控制 sleep 端 RM 开关。此机制可直接复用。

| BLE 指令 | 值 | 含义 |
|----------|-----|------|
| RM_ONOFF write | 1 | 机身切 RM RX 模式 |
| RM_ONOFF write | 0 | 机身切 BLE 低功耗模式 |

**时序要求**：
- RSL10 发送 RM_ONOFF=1 → 等待 N ms → 自身切 RM TX 推流
- 音频结束 → RSL10 停 RM TX → 发送 RM_ONOFF=0

### 3. RFX2401C RF 路径控制

基于测试数据，RFX2401C 控制策略：

| 场景 | TXEN (IO11) | RXEN (IO10) | 说明 |
|------|:---:|:---:|------|
| BLE 扫描/连接 | 0 | 1 | RX 通路，LNA 提升扫描距离 |
| RM TX 推流 | 1 | 0 | TX 通路，PA 提升发射距离 |
| 空闲/休眠 | 0 | 0 | 省电 |

**切换时序**：先关当前通路 → 再开目标通路，避免同时 HIGH。

### 4. 充电盒状态机

```
       ┌─────────────┐
       │   INIT      │  BLE 初始化，RFX2401C=RX
       └──────┬──────┘
              │
       ┌──────▼──────┐
       │  SCANNING   │  扫描两个机身 MAC
       └──────┬──────┘
              │ 扫到设备
       ┌──────▼──────┐
       │ CONNECTING  │  连接两个机身（并发）
       └──────┬──────┘
              │ 两个都连上
       ┌──────▼──────┐
       │  CONNECTED  │  BLE 连接保持，等待音频
       │  (待机)     │  机身=BLE 从机 600μA
       └──┬──────┬───┘
          │      │
   检测到音频   断连
          │      │
       ┌──▼──┐   │
       │STREAM│   │
       │RM TX │   │
       └──┬───┘   │
          │       │
      音频结束    │
          │       │
          └───┬───┘
              │
       ┌──────▼──────┐
       │  RECOVER    │  重连/重扫
       └─────────────┘
```

**状态转换条件**：

| 当前状态 | 事件 | 下一状态 | 动作 |
|----------|------|----------|------|
| INIT | BLE 就绪 | SCANNING | 启动扫描 |
| SCANNING | MAC 匹配 | CONNECTING | 停止扫描，发起连接 |
| CONNECTING | 两机身均连接 | CONNECTED | — |
| CONNECTING | 超时未连上 | SCANNING | 重新扫描 |
| CONNECTED | 检测到音频 | STREAMING | 发 RM_ONOFF=1 → 切 RFX2401C=TX → RM_Enable |
| CONNECTED | 机身断连 | SCANNING | 重新扫描 |
| STREAMING | 音频结束 | CONNECTED | RM_Disable → 切 RFX2401C=RX → 发 RM_ONOFF=0 |
| STREAMING | 机身断连 | SCANNING | 停 RM，重新扫描 |

### 5. 确认项

| 编号 | 事项 | 结论 |
|------|------|------|
| Q1 | AD6976 音频检测方式 | RSL10 DMIC 能量检测 |
| Q2 | AD6976→RSL10 音频数据接口 | DMIC |
| Q3 | 机身 RM RX↔BLE 切换指令 | 复用 Custom Service `RM_ONOFF` |
| Q4 | 双机身音频分配 | RM TX 广播，两个机身同时收同一路 |
| Q5 | 充电盒功耗要求 | 无特殊要求 |
| Q6 | S2 空板 IO11 拉不低（2.7V） | 先不管 |

## 测试数据分析与方案推论

### 关键发现

**1. BLE 扫描距离是瓶颈，不是 RM TX**

| 方向 | 最短距离 | 说明 |
|------|:---:|------|
| 充电盒→机身（扫描） | 5-11m | 机身 BLE 广播功率/天线决定 |
| 充电盒→机身（RM TX） | 20-56m | RM 链路余量远超 BLE |

充电盒扫机身最远 11m（带 PA），但机身接收 RM TX 能到 56m。**BLE 和 RM 覆盖范围严重不对称**。

**2. PA 的收益**

| | 无 PA | 有 PA | 提升 |
|------|:---:|:---:|:---:|
| BLE 扫描 | 5-8m | 8-11m | +3m |
| RM TX 穿墙 | 仅开发板 | 全部穿墙 | 质的飞跃 |

PA 在 RX 方向收益有限（+3m），在 TX 方向收益巨大（从无法穿墙到全部可穿墙）。

**3. 机身天线差异巨大**

| 设备 | 扫描距离 | TX 距离 |
|------|:---:|:---:|
| Smart1654 开发板 | 20m | 56m |
| Smart1654 机身 | 5m | 20m |

同一芯片方案，开发板是机身的 3-4 倍距离。机身天线/匹配是短板。

### 推论

**推论 A：机身必须支持 RM 超时自动切回 BLE**

```
充电盒 BLE 范围 5-11m，RM TX 范围 20-56m

用户场景：
1. 在 BLE 范围内，收到音频 → 切 RM RX → 正常
2. 用户走远（超出 BLE 范围 11m+），音频结束
3. 充电盒发 RM_ONOFF=0 → 机身 BLE 已断连 → 收不到
4. 机身永远停在 RM RX 模式 → 功耗 900μA 跑空
```

**方案**：机身 RM RX 模式下，N 秒无 RM 信号 → 自动切回 BLE 从机。

**推论 B：充电盒必须带 PA**

无 PA 的 RM TX 只在理想条件下覆盖 20-22m 且不能穿墙，充电盒的使用场景必然需要穿墙能力。PA 是必须的。

**推论 C：BLE 连接保持是系统薄弱环节**

机身 BLE 广播距离只有 5-11m，充电盒如果断连后再扫，不一定能扫回来。建议：

- 连接建立后尽量保持，BLE 断开才重新扫
- BLE connection interval 和 supervision timeout 适当配置，兼顾功耗和稳定性
- 机身 BLE 广播功率尽量拉满

## 可行性分析

### 已有基础（充电盒 TX 端）

| 功能 | 状态 | 说明 |
|------|:---:|------|
| BLE 扫描 MAC 匹配 | 已验证 | 多 peer 扫描正常 |
| BLE 多连接 | 已有代码 | PEER_COUNT=6，支持多 peer 并发连接 |
| DMIC 音频检测 | 已验证 | EMA 能量阈值检测，工作正常 |
| BLE → RM TX 切换 | 已验证 | RF_SwitchToCPMode + RM_Enable |
| RFX2401C TX/RX 控制 | 已验证 | 扫描时 RX 模式，TX 时 TX 模式 |
| BLE 指令 RM_ONOFF | 已有代码 | Custom Service 写特征值，已用于控制 sleep 端 |
| RM TX 广播推流 | 已验证 | 空旷 56m，带 PA 可穿墙 |

### 机身端需要新增

| 功能 | 说明 |
|------|------|
| RM 超时自动切回 BLE | **关键**：机身 RM RX 模式下 N 秒无 RM 信号，自动切 BLE 从机 |

机身端只有这一个新增需求，改动量很小。

### 充电盒 TX 端需要新增/调整

| 功能 | 说明 |
|------|------|
| 恢复 BLE 连接逻辑 | 当前纯扫描，需恢复：扫到 → 连接 → 保持连接 |
| 音频检测触发 RM_ONOFF | 检测到音频 → 发 RM_ONOFF=1 给两个机身 |
| 音频停止触发回切 | 音频结束 → 停 RM TX → 发 RM_ONOFF=0 |
| 断连处理 | 任一机身断连 → 重新扫描连接 |

### 功耗估算

| 状态 | RSL10 BLE | RFX2401C | 合计 |
|------|:---:|:---:|:---:|
| 待机（BLE 连接两个机身） | ~12mA | 0（RX 通路，LNA μA 级） | ~12mA |
| 推流（RM TX + PA） | ~12mA | +60mA | ~72mA |

> RFX2401C TX 模式实测多 60mA，仅推流期间发生。

### 风险点

| 风险 | 等级 | 应对 |
|---------------------------|:---:|----------------------------------------------|
| BLE 与 RM 覆盖不对称     | 中 | 机身 RM 超时自动回落 BLE（推论 A）           |
| S2 空板 IO11 2.7V        | 低 | 实测不影响功能，后续硬件可加下拉             |
| 两机身同时连接稳定性     | 低 | PEER_COUNT 机制已验证                         |
| AD6976 DMIC 静音时噪声   | 中 | 需调音频检测阈值，上线前实测                 |

### 结论

方案可行。核心技术点全部已验证，新增工作量集中在状态机调整和机身端 RM 超时逻辑。
