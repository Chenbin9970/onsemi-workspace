# 7160test 7100 I2C 通讯开发记录

> **2026-08-27**：硬件 I2C0 中断驱动方案打通，5s 心跳向 7100 发送 `04 88 01` 波形正确（地址 ACK + 数据 ACK + STOP 完整一帧）。
>
> 通讯对象从 BS300 DSP 改为 **7100**，I2C 驱动从软件 bit-bang 改为 **RSL10 硬件 I2C0**（中断驱动）。

## 一、背景

- `peripheral_server_sleep7160test` 工程从 `peripheral_server_sleep` 复制，BS300 功能已整体关闭（`app.h` 的 `BS300_ENABLE` 宏默认注释）。
- 与 7100 的通讯沿用原 BS300 的 I2C 总线，但软件 bit-bang 在 RSL10 16MHz 系统时钟下达不到目标速度（`7100connect.csv` 波形 SCL≈385kHz），改用**硬件 I2C0 外设**。

## 二、硬件配置

| 项目 | 值 |
|------|-----|
| SCL 引脚 | **DIO0** |
| SDA 引脚 | **DIO1** |
| 从机地址（7-bit） | **0x02**（总线地址字节 = 0x04，见踩坑 §5.2） |
| 总线帧 | `0x04` `0x88` `0x01`（地址 + 数据） |
| 速度 | prescale = `SystemCoreClock/(3×400kHz)-1` = 12 → **SCL≈410kHz** |
| 系统时钟 | 16MHz（`RFCLK_FREQ=16000000`） |

## 三、实现（硬件 I2C0 + 中断驱动）

### 3.1 为什么中断驱动

纯轮询（读 STATUS 判断事件）在**地址 ACK 后卡住**：RSL10 I2C 外设在 CM3 控制器模式下，每字节完成需要 CPU 经 **I2C 中断**响应（写下一个数据），否则外设保持 SCL 低等待。CMSIS 驱动（`I2C_RSLxx.c`）和官方样例（`remote_mic_tx_raw`）都依赖 `I2C_IRQHandler` 推进，必须照做。

### 3.2 传输流程（`code/i2c_7100_hal.c`）

```c
/* 全局传输状态 */
static const uint8_t *s_tx_buf; uint8_t s_tx_len, s_tx_idx;
static volatile bool s_tx_done, s_tx_ok, s_tx_active;

/* I2C 中断：每字节事件推进（参考样例 I2C_IRQHandler） */
void I2C_IRQHandler(void) {
    uint32_t st = Sys_I2C_Get_Status();
    if (st & I2C_BUS_ERROR)        { Sys_I2C_Reset(); s_tx_ok=false; s_tx_done=true; return; }
    if (st & I2C_STOP_DETECTED)    { s_tx_done=true; return; }        /* 传输完成 */
    if (!s_tx_active) return;
    if ((st >> I2C_STATUS_READ_WRITE_Pos) & 1) return;                /* 非写方向忽略 */
    if ((st >> I2C_STATUS_ACK_STATUS_Pos) & 1) { s_tx_ok=false; s_tx_done=true; return; } /* NACK */
    if (s_tx_idx < s_tx_len)  I2C->DATA = s_tx_buf[s_tx_idx++];       /* ACK → 发下一字节 */
    else                      { I2C_CTRL1->LAST_DATA_ALIAS = I2C_LAST_DATA_BITBAND; s_tx_done=true; }
}

bool i2c_7100_write(uint8_t addr, const uint8_t *data, uint8_t len) {
    /* 等上次传输结束 → 设置 s_tx_* 状态 → Sys_I2C_StartWrite(addr) → 等 s_tx_done */
}
```

### 3.3 初始化（`hw_ensure_init`）

```c
Sys_I2C_DIOConfig(DIO_6X_DRIVE | DIO_LPF_ENABLE | DIO_STRONG_PULL_UP,
                  I2C_7100_SCL_DIO /* 0 */, I2C_7100_SDA_DIO /* 1 */);
Sys_I2C_Reset();
I2C->CTRL0 = (I2C_CONTROLLER_CM3 | I2C_SAMPLE_CLK_ENABLE |
              I2C_AUTO_ACK_DISABLE | I2C_STOP_INT_ENABLE);   /* CM3 控制器 + 采样时钟 + 关自动ACK + STOP中断 */
I2C->CTRL0 = ((I2C->CTRL0 & ~I2C_CTRL0_SPEED_Mask) | (12U << I2C_CTRL0_SPEED_Pos));  /* 410kHz */
NVIC_SetPriority(I2C_IRQn, 4);  NVIC_ClearPendingIRQ(I2C_IRQn);  NVIC_EnableIRQ(I2C_IRQn);
```

`I2C_IRQHandler` 中断向量在 `startup_rsl10.S` 第 43 号已存在，直接定义实现即可。

## 四、5s 心跳发送（`app.c`）

RM 模式 200ms 定时器计数，每 25 tick（5s）向 7100 发送 `{0x88, 0x01}`（地址 `I2C_7100_ADDR=0x02`）：

```c
if (app_env.timer_200ms) {
    app_env.timer_200ms = 0;
    static uint8_t s_7100_hb_cnt = 0;
    if (++s_7100_hb_cnt >= 25) {
        s_7100_hb_cnt = 0;
        uint8_t pkt[2] = {0x88, 0x01};
        i2c_7100_write(I2C_7100_ADDR, pkt, sizeof(pkt));
    }
    ...
}
```

> 注意：挂在 RM 模式 200ms 定时器上，仅在 `audio_streaming`（RM 模式）运行；离开 RM 回 BLE 后停止。冷启动进 RM 是当前主场景，开机即周期发送。

## 五、踩坑记录（重要）

### 5.1 OD 输出占用 DIO0/DIO1（I2C 引脚冲突）

`Audio_Init()`（`app_init.c`）原来把 **DIO0 配成 OD_P 音频输出**（`DIO_MODE_OD_P`），与 I2C SCL=DIO0 冲突。

**修复**：注释 `app_init.c` 的 `Sys_DIO_Config(OD_P_DIO, ...)`，并去掉 `app.h` `AUDIO_CONFIG` 里的 `OD_ENABLE`。DIO0/DIO1 现在只用于 I2C。

### 5.2 从机地址左移（04 发成 08）

`Sys_I2C_StartWrite(addr)` 内部把 7-bit 地址**左移 1 位**（`addr<<1|R/W`）。初设 `I2C_7100_ADDR=0x04` 导致总线实际发 `0x08`。

**修复**：对照 `7100connect.csv` 波形解码，总线地址字节是 `0x04` → **7-bit 地址应为 0x02**（`0x02<<1=0x04`）。`I2C_7100_ADDR` 改为 0x02。

### 5.3 ACK 极性判断反了

`I2C_HAS_ACK = 0`——STATUS 的 `I2C_STATUS_ACK_STATUS_Pos`（bit0）**= 0 表示从机 ACK**（SDA 被拉低）。之前写成 bit0=1 才发数据，导致 7100 正确 ACK 后被误判 NACK、提前 STOP、总线停在低位。

**修复**：bit0=1 → NACK；bit0=0 → ACK 发下一字节。

### 5.4 上拉必须用强上拉

`Sys_I2C_DIOConfig` 用 `DIO_WEAK_PULL_UP`（弱上拉）时，发送后总线被拉低**挂死**（两线都低、无法恢复）。必须用官方样例的 **`DIO_STRONG_PULL_UP | DIO_6X_DRIVE | DIO_LPF_ENABLE`**。

### 5.5 纯轮询卡在地址 ACK 后

- 地址 ACK 后外设每字节需 CPU 中断响应，纯轮询检测不到正确事件标志 → SCL 停在低。
- **改用中断驱动**（§3.1）解决。
- `Sys_I2C_Config()` 或 write 前等总线空闲（`hw_wait_bus_free`）曾导致**完全不发地址**（"04都没了"），已回退为手动 `CTRL0` 配置 + 不做总线空闲等待。

### 5.6 BS300 兼容层

- I2C bit-bang 驱动从 `bs300_hal.c/h` 改名 `i2c_7100_hal.c/h`（SCL=DIO0、SDA=DIO1）。
- 新增 `include/bs300_hal.h` 兼容头：`#include "i2c_7100_hal.h"` + 符号映射（`bs300_i2c_write`→`i2c_7100_write` 等），**BS300 协议层（driver/startup/ram_sync）零改动**，BS300 关闭时被 gc-sections 剥离。
- `I2C_7100_ADDR=0x02` 时兼容头里 `BS300_I2C_ADDR` 同步变成 0x02（BS300 已关闭无影响）。
