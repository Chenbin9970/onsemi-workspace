# 7100 低电平增益全通道批量设置（块 07 整表重写）

> **2026-09-14** ｜ 通过抓包解析"程序0 所有通道 LowLevelGain 一次性改写"。
> 数据源：`p0setlowlevelgainallchannel0.txt`（全通道 LowLevelGain=0）、`p0setlowlevelgainallchannel1.txt`（全通道 LowLevelGain=1）。
> 关联：逐通道写法见 `7100_WDRC设置.md`，读取定位见 `7100_WDRC读取.md`。

## 1. 结论速览

逐通道写法（`A7 05 <参数号>` → `A7 04 08 00 00 <值>`）只能改一个通道的一个参数。
**整表重写**改用偏移 0 选中块起点，再用两条大帧把块 07 全部内容推下去：

```
A7 05 00 00 00 | 05 07 01 00 00      ← 块07、偏移0（逐通道写法此处是参数号，如 ch5 LL = 0x59）
A7 F4 ...  1012B                      ← 块07 前段，data[0:2] = 08 00 00
A7 61 ...    97B                      ← 块07 后段续帧，data[0:2] = 08 00 00
```

**LowLevelGain(ch N) 在块数据中的字节位置 = `66 + 51×(N−1)`**（N = 1..16，从 `A7 F4` 载荷第 0 字节起算）。

与逐通道写法（`7100_WDRC设置.md` 用**参数号**寻址）的换算：

```
块内字节偏移 = 66 + 3 × (参数号 − 0x15)        ← 仅对 0x15 ~ 0x18 成立
```

> 两条大帧合起来才是完整的块 07；`A7 F4` 的尾段被 I2C 帧边界截断，由 `A7 61` 续上。
> ⚠️ **该式不能外推**：OutputLimit 的写值字段是 **4 字节**（不是 3），说明各参数宽度不同 ——
> "每参数 3 字节"只是 `0x15`…`0x18` 恰好相距 3 字节的巧合，见 §5.1。

## 2. 块 07 载荷布局（`A7 F4` 的 1012 字节）

| 区段 | 长度 | 说明 |
|------|-----:|------|
| 前缀 | 66 B | 含一段 15 项、步进 500 的表（375 / 875 / 1375 … 7375），疑似频点表；其余**未确认** |
| 通道表 | 816 B | **16 通道 × 51 B** |
| 尾段 | 130 B | 与 `A7 61` 续帧同构的循环表（5 值一循环 `4B 01 05 04 02`，按 24bit 小端读），被帧边界截断 |

### 2.1 每通道记录 51 B（= 17 × 3 B）

51 B = 17 × 3 B。已确认的字段及其与**读取侧**（`0x0177` 块，147 bit/通道）的对应：

| 记录内偏移 | 24bit字 | 字段 | 编码 | 本抓包实测 |
|:---:|:---:|---|---|---|
| +0 | v0 | **LowLevelGain** | 值字节在 +0（高 2 字节为 0） | 0 / 1（两个抓包各为全通道同一值）|
| +3 | v1 | **UpperThreshold** | 值字节在 +3（高 2 字节为 0） | 全通道 110 |
| +6 | v2 | **HighLevelGain** | 值字节在 +6（高 2 字节为 0），8bit 有符号 | −16 −7 −3 −1 0 −1 −3 −5 −7 −9 −11 −14 −16 −19 −19 −19 |
| +9 | v3 | **OutputLimit** | **写值字段 4 字节（+9 ~ +12）**，byte0 = 值 | byte0 全 `FA` = −6；+10 随 OL 联动 |
| +12 … +48 | v4…v16 | **未确认** | — | 见 §2.3 |

**字内字节序**：24bit 小端，整数值在**低字节**。

> **注意**：16 通道全部记录里，**只有 +9 / +12 / +15 这三处的后 2 字节非 0**，
> 其余 14 个字都是零扩展的 8bit 值（高 2 字节恒 0）。所以"每参数 3 字节"的均匀网格
> 只在 +0 / +3 / +6 三处得到干净印证；+9 起可能实际是"1 字节值 + 紧跟 24bit 系数区"。
> 两种解释都能解释 OutputLimit 的值字节落在 +9，目前**无法区分**（见 §6）。

> 写入侧每通道 51 B，读取侧每通道 **147 bit**（≈18.4 B）—— 两者字节布局不同（写入多出大量系数/冗余字），
> 但 LL → UT → HL → OL 的**字段先后顺序一致**，且已知 4 个字段的值一一对应。前 4 个字段确认来自两侧对照。

## 3. 交叉验证

两份抓包逐字节比对，**只有 16 处差异**，位置全部落在 `66 + 51×k`（k = 0..15），即 16 个通道记录的 v0 低字节，值 `00` → `01`。
与"只改全通道 LowLevelGain"完全吻合，同时反证了记录起点（66）、步长（51）与字段位置（+0）。

写入值再与读取文档 `7100_WDRC读取.md` 比对：

| 字段 | 写入侧（本文） | 读取侧（0x0177） | 结论 |
|---|---|---|---|
| LowLevelGain | 记录 +0 低字节 | 读取单元 +0，7bit 无符号 | ✓ 位置与顺序一致 |
| UpperThreshold | 记录 +3 低字节 = 110 | 读取单元 +7，全通道 110 | ✓ |
| HighLevelGain | 记录 +6 低字节（有符号） | 读取单元 +14，8bit 有符号 | ✓ 15/16 吻合，**ch5 例外见 §6** |
| OutputLimit | 记录 +9 低字节 = `FA` = −6 | 读取单元 +22，全通道 −6 | ✓ |

**LowLevelGain 写入值 = 记录低字节原值**（不做编码变换）：与逐通道写法对照可验证 ——
`P0wdrclowlevergainchannel5set20csv.csv` 里 ch5 单值写为 `A7 04 00 00 00 08 00 00 14`（`0x14` = 20），
即写值 20 直接存入，本文块内 ch N 记录 +0 字节同理。

## 4. 完整写流程

```
预检     A7 01 00 03 00 02   (读 0x03，应答 46 03 00 00 00 1A)
静音     A7 01 00 00 00 25   (应答 46 00 00)
选程序0  A7 02 00 00 00 12 01
等空闲   A7 01 00 03 00 02   (应答 46 03 00 01 00 1A，第5字节=busy)
选块     A7 05 00 00 00 05 07 01 00 00     ← 块07、偏移0
写整表   A7 F4 ... (1012B)
续帧     A7 61 ... (97B)
提交     A7 02 00 00 00 10 01
等空闲   A7 01 00 03 00 02   (可能连续多次，直到 busy=00)
解除静音 A7 01 00 00 00 26
选程序0  A7 02 00 00 00 12 01
收尾     A7 01 00 00 00 0C → A7 01 00 03 00 02
```

与逐通道写法的流程骨架一致（预检静音 → 写 → 解除静音确认），差别只在"选块 + 写"两步。

## 5. 与逐通道写法的区别

| | 逐通道写 | 整表重写（本文） |
|---|---|---|
| 选块命令 | `A7 05 … 07 01 00 <参数号>`，如 ch5 LL = `0x59` | `A7 05 … 07 01 00 00`，偏移 0 |
| 数据帧 | `A7 04 … 08 00 00 <值>`（1 个值） | `A7 F4` 1012B + `A7 61` 97B（整块） |
| 可改范围 | 单个通道单个参数 | 全 16 通道、块内全部参数 |
| 参数号含义 | 块内**参数编号**（`0x15 + 0x11×(N−1)`），非字节偏移 | — |

> 参数号**不是**字节偏移：`0x59`(ch5 LL) 对应块内偏移 `270`。两者可换算，见 §5.1。

### 5.1 参数号 ↔ 块内字节偏移

```
块内字节偏移 = 66 + 3 × (参数号 − 0x15)
```

等价说法：**通道步长 `0x11`(17) ↔ 51 字节**、**参数步长 1 ↔ 3 字节**。
由来：`0x11` = 每通道参数个数，而 51 = 17 × 3 —— 若每个参数占 3 字节，两者正好对应。
参数号 `0x15`…`0x18` 这 4 个连续参数实测符合该模型（见下表），更靠后的未验证。

| 参数号 | 含义 | 公式预测偏移 | 实测 |
|:---:|---|:---:|---|
| `0x15` | ch1 LowLevelGain | 66 | ✓ 两抓包唯一差异字节所在 |
| `0x16` | ch1 UpperThreshold | 69 | ✓ 值 110 |
| `0x17` | ch1 HighLevelGain | 72 | ✓ 值 −16 |
| `0x18` | ch1 OutputLimit | 75 | ✓ 值字节 `FA` = −6 |
| `0x26` | ch2 LowLevelGain | 117 | ✓（= 66 + 51，通道步长） |
| `0x59` | ch5 LowLevelGain | 270 | ✓ 落在 ch5 记录起点 |

**`0x59` 这行是两个抓包之间的桥**：逐通道抓包 `P0wdrclowlevergainchannel5set20csv.csv` 用参数号 `0x59` 定位，
而整表写抓包里 ch5 的 LowLevelGain 正好在第 270 字节 —— 两种写法指向同一处。

**不能外推（原因已查明）**：OutputLimit 的**写值字段是 4 字节** ——
`p0channel1set-9` / `p0channel2set-8` 的帧是 `A7 07`（data = `08 00 00` + 4 字节），
而不是 LL / HL 的 `A7 04`（data = `08 00 00` + 1 字节）。这 4 字节占记录 +9 ~ +12。

所以 "+3 字节/参数" 的网格**从 OL 起就错位**，`0x19` 按公式推算到 +12 自然对不上
（该处低字节是 `78 / −2 / 70 …` 的杂乱值）。
**结论：`0x15`…`0x18` 相距 3 字节是巧合/结构体布局，不是通用规律。**

> OL 值字段的完整构成、16 通道默认表与构造规则见 `7100_WDRC设置.md` §3.2。

### 5.2 实际使用

| 想做的事 | 需要的输入 | 写法 |
|---|---|---|
| 点改一个参数 | **参数号** = `0x15 + i + 0x11×(N−1)`（i = 参数在通道内的序号，LowLevelGain 的 i = 0） | `A7 05 … 00 <参数号>` → `A7 04 … 08 00 00 <值>` |
| 整块覆盖 | **字节偏移** = `66 + 3i + 51×(N−1)` | 填满 1012 B 全量表 → `A7 F4` + `A7 61` |

> 逐通道写只发 4 B 数据帧、只动目标参数；整表写是 1012 B 全量覆盖，调用方必须持有整块参数内容。
