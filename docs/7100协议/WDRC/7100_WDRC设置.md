# 7100 WDRC 设置（单通道写）

> **2026-09-04 创建，2026-09-15 补 OutputLimit** ｜ 通过抓包解析 WDRC（宽动态范围压缩）参数写入。
> 本文覆盖实际使用的三个参数：**LowLevelGain / HighLevelGain / OutputLimit**，均按**单通道写**（循环 16 通道）。
> 现有抓包全是**设备程序 1**（选程序帧 `A7 02 00 00 00 12 01`）；程序号 1-4 的取值约定见 §7。
> 数据源：`P0wdrcchannel1set27/28`（实为 ch2 LowLevelGain）、`P0wdrchighlevergainchannel1set-6/-7`（实为 ch2 HighLevelGain）、
> `P0wdrclowlevergainchannel5/10set20`、`P0wdrchighlevergainchannel5set10`、`p0channel1set-9` / `p0channel2set-8`（OutputLimit）。
> ⚠️ 部分文件名通道号标错（见 §5），以实测为准。

## 1. 结论速览

三个参数走同一套序列：`A7 05` 选块 + 参数号，再用数据帧写值。

```
A7 05 00 00 00 | 05 07 <prog> <参数号 16-BE>   ← 选程序 + 通道 + 参数
A7 0N 00 00 | 00 08 00 00 <值字段>           ← 写值
```

| 参数 | 参数号 (ch N) | 数据帧 | 值字节数 | 编码 | 范围 |
|---|---|:---:|:---:|---|---|
| **LowLevelGain** | `0x15 + 0x11×(N−1)` | `A7 04` | 1 | 8bit 补码 | −30 ~ 60 |
| **HighLevelGain** | `0x17 + 0x11×(N−1)` | `A7 04` | 1 | 8bit 有符号（补码） | −30 ~ 60 |
| **OutputLimit** | `0x18 + 0x11×(N−1)` | **`A7 07`** | **4** | byte0 = 值；其余 3 字节见 §3.2 | **0 ~ −60** |

> ⚠️ **OutputLimit 的帧形状与另两个不同**：数据帧是 `A7 07`（data 7 字节 = `08 00 00` + 4 字节值），
> 且后 3 个值字节不能凭空填 —— 必须按 §3.2 的规则构造，只发 1 个字节不行。

### 设置 / 读取速查

| | LowLevelGain (ch N) | HighLevelGain (ch N) | OutputLimit (ch N) |
|---|---|---|---|
| **设置参数号** | `0x15 + 0x11×(N−1)` | `0x17 + 0x11×(N−1)` | `0x18 + 0x11×(N−1)` |
| **设置写** | `A7 05 <参数号>` → `A7 04 08 00 00 <值>` | 同左（值有符号） | `A7 05 <参数号>` → `A7 07 08 00 00 <4 字节>` |
| **读取命令** | `A7 01 00 77 01 38` → 0x0177 块 | 同左 | 同左 |
| **读取位置** | bit `446+(N-2)×147` +0（7bit 无符号） | 同 +14（8bit 有符号） | 同 +22（8bit 有符号） |
| **值范围** | −30 ~ 60 | −30 ~ 60 | 0 ~ −60 |

> 读取解码详见 `7100_WDRC读取.md`。

### 全通道批量写（整表重写）

上面的写法一次只能改一个通道的一个参数。若要**全部 16 通道**一起改，改用偏移 0 选块 + 两条大帧把块 07 整表写下去：

```
A7 05 00 00 00 05 07 01 00 00      ← 块07、偏移0（不是参数号）
A7 F4 ...  1012B                   ← 块07 前段，data[0:2] = 08 00 00
A7 61 ...    97B                   ← 块07 续帧
```

**LowLevelGain(ch N) 在 `A7 F4` 载荷内的偏移 = `66 + 51×(N−1)`**（N = 1..16）。

> 注意：逐通道写法的参数号 `0x59`(ch5 LL) 与块内字节偏移 `66 + 51×4 = 270` 不是一回事，不要混用。
> 机制、块布局与字段表详见 `7100_低电平增益全通道批量设置.md`。
>
> ⚠️ **本方案不采用**：每次要发 1109 字节（`A7 F4` 1012B + `A7 61` 97B），数据量太大。
> 实际实现按本文的单通道写**循环 16 通道**。
> ⚠️ 另注意：OL 的值字段是 **4 字节**（见 §3.2），所以"每参数 3 字节"的均匀网格**不成立** ——
> `66 + 3×(参数号−0x15)` 只在 `0x15`…`0x18` 上巧合成立，**不能用来推导其它参数的位置**。

## 3. 值编码

| 参数 | 编码 | 示例 |
|------|------|------|
| LowLevelGain | 8bit 补码（1 字节） | 20→`14`，27→`1B`，**−2→`FE`** |
| HighLevelGain | 8bit 补码（1 字节） | −6→`FA`，−7→`F9`；正值直接存 10→`0A` |
| OutputLimit | **4 字节**，见 §3.2 | ch1 −6→`FA EA 57 4E`；ch1 −9→`F7 E7 57 4E` |

### 3.1 LowLevelGain / HighLevelGain

值字段 1 字节，直接就是参数值，**负值用 8bit 补码**（LL 与 HL 同编码）。
数据帧 4 字节 = `08 00 00 <值>`，帧头 `A7 04`。

> **LL 负值编码已实测**：`p0lowchannel2levelgainset-2.txt` —— ch2 LL = −2 → 写值字节 `FE`。
> 7bit 补码会是 `7E`，已排除。
> （`7100_WDRC读取.md` 里说的"7bit"只是读取块 `0x0177` 的**打包宽度**，写入侧不受此限。）

### 3.2 OutputLimit（4 字节值字段）

数据帧是 `A7 07`，data = `08 00 00` + **4 个值字节**：

| 值字节 | 含义 |
|:---:|---|
| byte0 | **OL 本身**，8bit 补码（0 → `00`，−6 → `FA`，−9 → `F7`） |
| byte1 | **OL + K_ch**，与 OL 严格 1:1 联动（K_ch 为逐通道常量） |
| byte2 / byte3 | 逐通道常量，**与 OL 无关**（改 OL 时不变） |

实测验证（3 通道 × 3 取值，全部吻合）：

| 通道 | 默认 OL = −6 | 改为 | 按规则预测 | 实测 |
|:---:|:---:|:---:|:---:|:---:|
| ch1 | `FA EA 57 4E` | −9 | `F7 E7 57 4E` | ✓ 一致 |
| ch2 | `FA E5 EA FE` | −8 | `F8 E3 EA FE` | ✓ 一致 |
| ch16 | `FA ED 9F 52` | **0** | `00 F3 9F 52` | ✓ 一致 |

> ch16 的 **OL = 0** 这条最关键：byte1 从 `ED`(−19) 变成 `F3`(−13) = 0 + K_ch16，
> **跨过 0 点没有补码回绕**，证明 byte1 就是 `OL + K_ch` 这个线性关系，而非某种取模/偏移写法。

**16 通道默认表**（取自 `p0setlowlevelgainallchannel0.txt`，OL = −6 状态，块 07 记录 +9..+12）：

| ch | 4 字节 | K | | ch | 4 字节 | K |
|:--:|---|---|---|:--:|---|---|
| 1 | `FA EA 57 4E` | −16 | | 9 | `FA E8 FD 84` | −18 |
| 2 | `FA E5 EA FE` | −21 | | 10 | `FA E8 FD 71` | −18 |
| 3 | `FA E3 08 46` | −23 | | 11 | `FA E9 17 AF` | −17 |
| 4 | `FA E2 88 64` | −24 | | 12 | `FA EA DC D6` | −16 |
| 5 | `FA E2 FD 80` | −24 | | 13 | `FA EB 0B 47` | −15 |
| 6 | `FA E4 06 11` | −22 | | 14 | `FA EB EE 18` | −15 |
| 7 | `FA E8 35 E8` | −18 | | 15 | `FA EC 79 C1` | −14 |
| 8 | `FA E9 79 7B` | −17 | | 16 | `FA ED 9F 52` | −13 |

**构造规则**（OL 范围 0 ~ −60，byte0 / byte1 都落在 int8 内，不会回绕）：

```
data[0..2] = 08 00 00
data[3]    = OL & 0xFF
data[4]    = 表[ch].byte1 + (OL + 6)     /* 即 OL + K_ch */
data[5]    = 表[ch].byte2
data[6]    = 表[ch].byte3
帧          = A7 07 00 00 + data
```

> ⚠️ 表里的 `byte1`~`byte3` 只来自**一次默认状态下的抓包**。若这些字节被其它工具改过，表就不再准 ——
> 它们的物理含义未知（见 §6）。写完后可读 `0x0177` 核对 OL 自身是否生效。
> ⚠️ 与 7111 手册**不通用**：7111 的 WDRC Output Limit 是 6 字节复合编码（`00 00 FF DF FD 71`，
> 其中 `DF = 0xE0 + setvalue`），不能照搬。

## 4. 完整写流程

单通道写（三个参数同构，只有"写值"帧不同）：

```
预检     读 0x03   A7 01 00 03 00 02            → 46 03 00 00 00 1A
静音              A7 01 00 00 00 25            → 46 00 00
选程序 <prog>     A7 02 00 00 00 12 <prog>         → 46 00 00
等空闲            A7 01 00 03 00 02            → 46 03 00 <x> 00 1A   (第5字节 = busy)
选块              A7 05 00 00 00 05 07 <prog> <参数号 16-BE>   → 46 00 00
写值   LL / HL    A7 04 00 00 00 08 00 00 <1 字节值>
       OL         A7 07 00 00 00 08 00 00 <4 字节值>   ← 帧头不同，见 §3.2
提交              A7 02 00 00 00 10 01         → 46 00 00
等空闲            A7 01 00 03 00 02            (可能连续 2 次，直到 busy=00)
解除静音          A7 01 00 00 00 26            → 46 00 00
选程序 <prog>     A7 02 00 00 00 12 <prog>
收尾              A7 01 00 00 00 0C → A7 01 00 03 00 02
```

> `A7 01 00 03 00 02` 的应答 `46 03 00 <x> <busy> 1A` 中**第 5 字节是忙标志**：
> `00` = 写完，`01` = 仍忙，需重发该查询（`p0channel1set-9` / `p0channel2set-8` 里都能看到这一轮重试）。

## 6. 待确认

- **OutputLimit 的 byte1 / byte2 / byte3 含义未知**：byte1 = `OL + K_ch`（K 逐通道 −24…−13），
  byte2 / byte3 为逐通道常量。与 OL 的线性关系已实测锁死（3 通道 × 3 取值，含 0 点），
  但三者的物理意义不明 —— 也无法排除它们会被其它工具的操作改动（那样 §3.2 的表就失准）。
- 其他 WDRC 参数（Threshold / 压缩比 / Attack / Release 等）的基址——
  **各参数宽度不同**（LL / HL 为 1 字节，OL 为 4 字节），不能假设统一宽度。
- HighLevelGain 负值范围上限
- ch0 是否存在（公式 N 从 1 起）

## 7. 实现（C 代码）

`remote_mic_rx_coex_1664/code/dsp_7100_cmd.c`（声明在 `include/dsp_7100_cmd.h`）。
三个接口复用现有异步会话框架（新增会话类型 `A7_KIND_WDRC`，骨架与降噪一致）：

```c
bool dsp_7100_set_low_level_gain (uint8_t prog, uint8_t ch, int8_t val);
bool dsp_7100_set_high_level_gain(uint8_t prog, uint8_t ch, int8_t val);
bool dsp_7100_set_output_limit   (uint8_t prog, uint8_t ch, int8_t val);
```

| 项 | 说明 |
|---|---|
| 入参 | `prog` **1-4**，`ch` **1-16**，`val` **绝对值**（不是增量，与 `set_eq` 不同） |
| 值范围 / 钳位 | LL `-30..60`、HL `-30..60`、OL `-60..0`（越界钳位）|
| 返回 | `true` = 已受理（异步）；完成看日志 `[7100] --- session done ok=? ---` |
| 时长 | 8 条命令 = 16 tick × 200ms ≈ **3.2s** |
| 互斥 | 会话进行中 `dsp_7100_cmd_busy()` 为真，期间不要发起新会话 |
| 成功后 | 回写读回缓存 `wdrc_ll/hl/ol[]` 并请求落盘 |

会话骨架（同降噪）：`静音 → 选程序 → 选块 → 写值 → 提交 → 解除静音 → 选回程序1 → commit`

实现内要点：
- OL 用专用构造器（`A7 07` + 4 字节值字段），LL / HL 走既有的单值构造器（`A7 04`）。
- 默认表 `s_wdrc_ol_tail[16][3]` 就是 §3.2 那张表的后 3 字节；byte0 按目标值算，byte1 按 `val + K_ch` 平移。
- 地址宏 `A7_WDRC_{LL,HL,OL}_ADDR(n)`，其中 `OL = LL + 3`。

> ⚠️ **与 `set_eq` 的交互**：`set_eq` 的模型是"设备值 = 读回基准 + 该段 eq"，而本接口写绝对值并直接覆盖基准。
> 若该通道所属 EQ 段的偏移非 0，两边的账会差一个 eq 量（当前 EQ 默认 0，实现里未处理，注释已标明）。
> ⚠️ **prog 取值**：设备侧是 **1-4**，App 侧 scene 是 **0-3**，调用时要 `scene + 1`。
> 现有代码注释里把 `12 01` 称作"程序0"，是沿用了 App 侧叫法，实际还是设备程序 1。
