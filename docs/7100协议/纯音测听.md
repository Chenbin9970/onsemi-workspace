# 7100 纯音测听（ITG 出音 / 停音）

> **2026-09-15** ｜ 从逻辑分析仪抓包 `tone<hz>hz<db>db.txt`（15 条）反解出来的 7100 纯音命令。
> 关联：BLE 侧命令见 `瑞听设置指令.md`；本文件只管 7100 I2C 这一层。

## 1. 帧格式

出音与停音是**同一条命令**，靠第 7 字节的使能位区分：

```
A7 07 00 00 00 | 2E <en> <freq16-BE> <level24-BE>
└─ len16=7 ──┘   └ addr=0 ┘
```

| 字节 | 含义 |
|------|------|
| `A7 07 00` | 命令号 + len16 = 7（小端） |
| `00 00` | addr16 = 0 |
| `2E` | 子命令：纯音 |
| `en` | **`01` = 出音 ／ `00` = 停音** |
| `freq16-BE` | **频率，直接就是 Hz**（如 `03E8` = 1000、`07D0` = 2000） |
| `level24-BE` | 电平（见 §2） |

**停音会把频率和电平一起清零**，不是只翻使能位：

| | 帧 |
|---|---|
| 出音 1000Hz 55dB | `A7 07 00 00 00` `2E 01 03 E8 00 09 AA` |
| **停音** | `A7 07 00 00 00` `2E 00 00 00 00 00 00` |

**整个交互只有 3 个包**：写帧 → 读应答 `46 00 00` → `82`。
**没有 mute / 选程序 / confirm / commit** —— 与 WDRC 那套写会话完全不同，是独立的一条命令。

## 2. 电平编码

```
level24 = round( K × 10^((db + C(f)) / 20) )        K = 4.39902
```

- `K`：全局常数，拟合值（见 §4）
- `C(f)`：**逐频率的整数 dB 修正**

### 推导过程

1. **同一频率下**，+5 dB 对应 ×1.7783 = `10^(5/20)`，且 1000 Hz 从 80→100 dB（+20 dB）正好 ×10
   → **电平与幅度成正比**（`10^(dB/20)`），不是功率关系
2. 反解常数 `A(f) = level / 10^(dB/20)`：500→3.921、1000→4.399、2000→4.399、
   3000→2.473、4000→5.538、6000→22.047
3. 把 `A(f)/A(1000)` 换成 dB：**−0.999 / 0.000 / 0.000 / −5.003 / +1.999 / +13.997**
   —— 全部落在**整数**上（偏差 < 0.005 dB），所以逐频率部分是 `10^(C/20)`，`C` 为整数
4. 代回 15 个抓包点，最大偏差 **0.5 LSB**（即最后一次取整）

## 3. 实现（C 代码）

`remote_mic_rx_coex_1664/code/dsp_7100_cmd.c`：

```c
bool dsp_7100_play_tone(uint16_t freq_hz, uint8_t db);
bool dsp_7100_stop_tone(void);
```

- 走同一套 tick 机制，但会话**只有 1 条命令**（2 tick ≈ 0.4s），无公共帧
- `db` 范围 **20 ~ 100**；`freq_hz` 必须是**已标定频点**，否则返回 false
- 电平用**查表**（`s_tone_level[100]`，索引 `k = db + C(f)`，k ∈ 15…114）
  —— 工程未链接 libm、RSL10 无 FPU，与 1654 的 `bs300_beep_frac24_table` 同一做法

BLE 侧（`ble_rempro_cmd.c`）：`SetPlayVoice (13)` / `SetStopVoice (14)`，
`Spectrum 0-16 → 250/500/1000/…/8000 Hz`，`Decibel 20-100`。

## 4. 待确认 / 风险

- **`K = 4.39902` 的出处不明**。3 个整数偏差点、15 条抓包把它约束在
  **[4.399015, 4.399024]**（宽仅 9e-6），但试过 `2^24` / `2^23` / 整数 dB 偏移等各种
  拆法都凑不出干净的表达式 —— **很可能是整机校准常数（接收器灵敏度）**。
  若换机需要重标，这张表就不能硬编码，得改成从设备读取或出厂标定。
- **`C(f)` 只标定了 6/17 个频点**。缺：**250、1500、2500、3500、4500、5000、5500、
  6500、7000、7500、8000** —— 这些频点现在会返 `false`（BLE 侧回 `Flag=1`）。
  补齐方法：**固定一个 dB（如 50），把缺的频点各抓一条**，按 §2 步骤 3 反解 `C`。
- **模型不唯一**：App 只发 5 的倍数 dB，所以"连续公式"与"5dB 步进查表"在数据上无法区分
  （对实现无影响）。要区分可抓一条非 5 倍数的 dB。
- **未验证**：只在离线比对过抓包，**未上板**。
