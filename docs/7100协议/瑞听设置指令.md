# 瑞听协议 — 增益 / MPO / HighLevel 设置指令

> **2026-09-15 创建** ｜ 从 `docs/瑞听听力产品控制接口文档(1).md` 摘出与 7100 WDRC 相关的三条设置指令。
> 用途：App（瑞听 HDLC）→ 设备 → 7100 I2C，把验配值落到 WDRC 参数上。
> ⚠️ 原文档的 `## SetGain (ID:6)` 等小节**请求/响应格式是空的** —— docx 转换时表格与标题脱节，
> 实际全部堆在文件第 1000 行以后，本文按 `CMD_ID` 归属重新摘录。

## 0. 命名空间陷阱（先看）

原文档有**两套 SYS_ID**，同号不同义，实现时不能只看 CMD_ID：

| SYS_ID | CMD 6 | CMD 7 | CMD 8 |
|:---:|---|---|---|
| **0** | **SetGain** | **SetMPO** | SetCompressRatio |
| 1 | 初始化状态 | WDRC Data_Table（32/64 B） | 经典蓝牙连接状态 |

本文只涉及 **SYS_ID = 0**。

## 4. 与 7100 WDRC 的对应（**已定**）

| 瑞听指令 | 索引空间 | → 7100 WDRC 参数 | 7100 参数号 (ch N) | 7100 值字段 |
|---|---|---|---|---|
| **SetGain** (CMD 6) | Spectrum `0~31` | **LowLevelGain** | `0x15 + 0x11×(N−1)` | 1 字节，无符号 |
| **SetHighLevelGainData** (CMD 29) | Channel | **HighLevelGain** | `0x17 + 0x11×(N−1)` | 1 字节，有符号 |
| **SetMPO** (CMD 7) | Channel | **OutputLimit** | `0x18 + 0x11×(N−1)` | 4 字节，见下 |

MPO = Maximum Power Output（最大输出量），语义上就是 OutputLimit。
7100 侧写序列、参数号、帧格式见 `7100协议/WDRC/7100_WDRC设置.md`；
对应的 C 接口是 `dsp_7100_set_{low_level,high_level}_gain()` / `dsp_7100_set_output_limit()`。

### 索引映射（**已定**）

**只取 `Spectrum 0~15`，直接对应 ch1~ch16**（Spectrum N → 参数号 ch N+1）；`Spectrum 16~31` 不使用。

SetHighLevelGainData / SetMPO 用 Channel，同样是通道号 0 起 → 参数号 ch N+1。

> 注：文档里 `Spectrum 0` 标着"总增益"，实际按用户要求当 **ch1** 用。

### 值换算（**已定**）

三条都是 **1 LSB = 1 dB 的纯偏移**，两端跨度与 7100 侧一致：

| 瑞听 | 值域 | 换算 | 7100 值域 |
|---|---|---|---|
| **SetGain** `Decibel` | 0 ~ 90 | **`LL = Decibel − 30`** | −30 ~ 60 |
| **SetHighLevelGainData** `档位值` | 0 ~ 90（同 SetGain） | **`HL = 档位值 − 30`** | −30 ~ 60 |
| **SetMPO** `MPO 档位值` | 0 ~ 60 | **`OL = 档位值 − 60`** | −60 ~ 0 |

> 例：SetGain = 30 → LL = 0；SetGain = 90 → LL = 60；SetMPO = 60 → OL = 0；SetMPO = 0 → OL = −60。

### LowLevelGain 的负值编码（✅ 已实测）

`LL = Decibel − 30` 会产生 **−30 ~ −1 的负值**，实测确认用 **8bit 补码**：

`p0lowchannel2levelgainset-2.txt` —— ch2 LL = **−2** → 写值字节 **`FE`**
（7bit 补码会是 `7E`，已排除；与 HighLevelGain 同编码）。

> `7100_WDRC读取.md` 里写的"7bit"只是读取块 `0x0177` 的**打包宽度**，写入侧不受此限。

### Device_Type = 0（左右）时是否装双耳数据

文档在 `SYS_ID=1` 的 CMD 7 写过"Device_Type 为 0 时发左右共 64 字节"，
但这三条**没写**。若同样加倍，单耳设备要取自己那一半。抓包时顺便看一眼实际发的 `Device_Type` 即可判断。

### 频点表疑似

原文档第 2366-2399 行有一张 **32 点频段表**（0, 250, 500, 750 … 7750 Hz，步进 250），
条目数正好是 32，与 SetGain 的 `Spectrum 0~31` 吻合，疑似同一张频点表
（但原表挂在 `SYS_ID=1` 的 CMD 7 下，归属存疑）。

> ⚠️ 别和我们之前在 7100 块 07 里挖出的 **15 点、步进 500** 那张（375 / 875 / … / 7375）混为一谈 ——
> 那张在 `7100_低电平增益全通道批量设置.md` §2，是 7100 I2C 侧的东西。

## 5. 读取配套

| CMD | 名称 | 差异 |
|:---:|---|---|
| 22 | GetGainData | 响应多一个 `Channel_Number`(1)，再重复 `{Spectrum, Decibel}` |
| 23 | GetMPOData | 重复 `{Channel, MPO}` |
| 30 | GetHighLevelGainData | 重复 `{Channel, High Level Gain}` |
| 31 | GetFittingData | 一次给全：`Turn_Number` · `Gain_Number` · `Compress_Number` · `MPO_Number` · `HighLevel_Number` + 四张表 |

> ⚠️ SetGain 请求写 `Spectrum 0~31`，GetGainData 响应却写 `0~32` —— 原文档自相矛盾，需实测。
